# Implementation Plan

PR #34（merge commit `399e8ba`）のレビューを経た追随作業。**1.8.0 の公開前に完了させることを前提にしている**（PR #34 は未公開なので、新ツールの応答の形を変えても誰も壊れない）。

実装の詳細（対象ファイル・関数名・型定義・応答フィールドの構造）は design.md が持つ。本ファイルは作業の単位と順序だけを扱う。

`(P)` は並行実行可能なタスク。`_Depends:_` は同一ファイルへの競合または成果物の依存があるものだけを明示している。

> **完了済み。** 本ファイルは実装当時の作業単位と順序の記録である。以下のタスクが参照している design.md の「Testing Strategy」（どのテストをどう変えるかの一覧）は、実装完了後の整理で削除した。現在はテストコード自体がその記録である。

## 並行実行の判断

`(P)` を付けたのは 2.1・4.1・6.1 の 3 件で、いずれも編集対象のファイルと境界が他のタスクと重ならない。

似て見えるが並行にできないものを明示する。

- **3.x はタスク 1 の後**。どちらもアウトライン解析ユーティリティを編集するため
- **4.2 は 3.2 の後**。どちらもアウトライン取得ツールを編集し、かつ 4.1 の整形処理を使う
- **6.2 は 5.1 の後**。どちらも編集ツールの登録層を編集する
- **5.3 は 5.1 の後**。どちらも編集ツールのテストを編集する
- **2.2 は 1.2 の後**。アウトライン取得ツールの説明文に、置き換えで得た振る舞い（下線形式の見出しの検出）を書き添えるため
- **2.3 はタスク 4 と独立**。応答の同一性を 2 ツールの突き合わせで検証する形にすることで、権限情報の形の変更から切り離してある

## 対象外

- **CI の整備**（このリポジトリには CI チェックが 1 つも無い。本 spec より広い課題。その結果としてテスト差分の管理が唯一の検出手段になることは Requirement 7 に織り込んである）
- **要約情報を返すツールの変更**（別の API を呼んでおり、ページのメタデータ取得の代替にはならないが、その整理は範囲外）
- **従来の名前の意味の入れ替え**（1.7.0 で公開済みのため、別名として動作を維持する）
- **GROWI 独自記法への対応**（完全一致には GROWI 本体のプラグイン群が必要で、publish されていない）
